# 동시성 제어

## 동시성

### 동시성 이란?

- 여러 작업이 동시에 실행되는 것 처럼 보이게 만드는 것을 의미하며,
- 한대의 CPU가 빠르게 번갈아가며 작업을 수행하거나, 멀티코어 환경에서 실제로 병렬 처리가 되는 것을 의미합니다.

### 동시성 문제란?

- 동시성 문제가 발생하는 이유는 공유중인 자원에 두 개이상의 요청이 접근하여 정보를 수정 하려는 경우에 발생합니다.
- 조회와 수정을 하는 두 요청이 동시에 동일한 자원에 접근하는 경우 후에 수정이 완료된 정보로 DB가 덮어씌워져 정합성을 훼손할 수 있습니다.

## 동시성 제어 기법

### 비관적 락

- 트랜젝션 단위로 공유 자원에 대한 접근을 막고, 다른 요청은 대기

### 낙관적 락

- version 칼럼에 추가하고, 조회 후 수정 시 조회된 version의 조건문을 함께 검증
- 실패 시 재시도 로직 필요

### 분산락

- 분산 환경에서 공유된 자원을 기준으로 락을 관리
- 메모리 기반의 Redis 등을 사용

### 메세지 큐

- 요청을 큐에 넣고, 순차적으로 하나씩 처리

## 주요 기능 중 동시성이 발생할 수 있는 시나리오

### 포인트 충전 경쟁 조건

- 요청 1, 2가 동시에 한 userId에 충전을 요청
- 초기 조회한 포인트를 기준으로 각 요청이 수정 시도
- 늦게 수정이 완료된 요청값으로 포인트가 수정되어 데이터 유실


### 포인트 사용 경쟁 조건

- 요청 1, 2가 거의 동시에 한 userId로 사용을 요청
- 초기 조회된 값에서 사용 포인트를 차감하여 DB 수정 시도
- 늦게 완료된 요청에 의하여 포인트가 저장되어 사용 데이터가 유실

### 데이터 불일치

- 동일한 userId와 포인트 칼럼이 참조되는 충전/사용은 동시성 문제를 유발할 수 있음
- 조회/이력 조회 시 정합성을 보장하지 못하거나, 수정은 되었으나 기록이 남지 않을 수 있음

## 적용가능한 동시성 제어

### Node.js 기반 요청 큐 구현

- [queue.ts](../src/common/concurrency/queue.ts)
  ```typescript
  const userQueues = new Map<number, Promise<any>>();

  export const enqueue = async <T>(
    userId: number,
    task: () => Promise<T>,
  ): Promise<T> => {
    const prev = userQueues.get(userId) || Promise.resolve();
    const next = prev.then(task).finally(() => {
      if (userQueues.get(userId) === next) {
        userQueues.delete(userId);
      }
    });
    userQueues.set(userId, next);
    return next;
  };
  ```
  - userId를 기준으로 메모리 기반의 요청 큐를 생성
  - 단일 환경의 단일 스레드에선, 서버가 죽거나 재실행되지 않는 한 순차적으로 실행 가능
